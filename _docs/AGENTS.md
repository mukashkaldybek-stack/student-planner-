# AGENTS.md — AI Development Instructions

## 1. Project Overview

Student Planner is a web application that helps students organize academic tasks, manage deadlines, and track their study progress.

Before making changes, read `_docs/plan.md` and follow the project requirements.

## 2. General Rules

- Work on one GitHub Issue at a time.
- Do not implement features that are outside the approved scope.
- Read the issue description and acceptance criteria before starting work.
- Keep changes small and easy to review.
- Explain important decisions in simple language.
- Do not claim that a task is complete unless its acceptance criteria have been checked.

## 3. Planning Rules

- Define the goal and acceptance criteria before implementation.
- Use `_docs/task-template.md` when preparing tasks.
- Keep the GitHub Issues backlog organized.
- Ask for clarification when requirements are unclear.

## 4. Engineering Rules

- Follow the project plan and existing architecture.
- Write tests for implemented functionality.
- Run relevant tests before reporting completion.
- Do not close GitHub Issues yourself.
- Commit changes regularly.
- Report what was implemented and which tests were run.

## 5. Quality Assurance Rules

- Check every acceptance criterion against the actual implementation.
- Run the relevant tests.
- Report PASS or FAIL with evidence.
- Do not fix the implementation during the QA review.
- Do not close issues.

## 6. Issue Completion

A GitHub Issue can be closed only after all acceptance criteria have been verified and QA reports PASS.

If QA reports FAIL, return the issue to engineering for corrections.

## 7. Documentation

Keep project documentation consistent with the implementation.
